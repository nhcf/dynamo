01 / Planner 的职责与本章边界

Planner 是有状态的容量控制器：采集流量与引擎观测，估算容量和排队压力，合并候选方案与资源约束，再经 Connector 提交副本目标。它同时是可观测数据的消费者与生产者。

本章固定在 2f296b592（workspace 1.7.0 开发基线），只分析本地源码，不读取集群、不执行扩缩容。线上 1.4.1 等版本需单独核对实现。重点是在线 builtin 路径；Global Planner、外部插件、batch、replay、retune 只标出边界，不声称已逐项完成分析。

输入通道从哪里来控制用途
Prometheus 查询Frontend / Router 的窗口化请求与 Histogram；引擎 speculative 指标流量形状预测、容量下界、KV/accept-length 元数据
Runtime FPM 事件Worker/rank 调度遥测，经 Rust subscriber 跟踪即时负载、性能模型调优、空闲与完整性检查
部署状态 / Worker 元数据Environment / Connector、发现信息、模型部署卡Ready/Expected/Pending、副本状态、GPU形状、引擎上限
可选 batch 输入BatchMetricsConfig 的直接 OpenMetrics 端点batch-aware planning；与普通 Prometheus 查询不同，本文不深挖策略
不要把 FPM 事件订阅、FPM 文件捕获和 Planner 自身的 /metrics 当成同一条链路：Planner 在线消费 FPM 不依赖先把 gzip JSONL 导入 Prometheus。

03 / 模式、优化目标与观测依赖

拓扑 mode 与 optimization_target 是两个维度。agg 控制组合 Worker，disagg 分别控制 Prefill/Decode，prefill/decode 控制单池。optimization_target 决定如何使用观测数据。

非 SLA：配置归一化后强制 load scaling，关闭 throughput scaling。

throughput / latency 采用内置 queue / KV 阈值；load 使用显式阈值。optimization_target=throughput 不是 enable_throughput_scaling=true，两者名称相近但含义不同。

SLA：可启用吞吐、负载或两者。

吞吐路径使用 traffic + 性能模型；SLA load 路径使用 FPM + 性能模型，也可能查询 KV hit rate / accept length。两者一起使用时吞吐路径提供下界，负载路径处理较快变化。

825
826        Pipeline fires at ``self._last_tick_s + scale_interval`` —
827        a single base cadence with no dual-cadence merge. Per-plugin
828        ``execution_interval_seconds`` throttling (in
829        ``PluginScheduler._is_due``) handles which plugins actually
830        fire each tick.
831
832        Observation collection (``need_traffic_metrics``,
833        ``traffic_metrics_duration_s``) is gated on whether any
834        registered plugin both lists ``observations.traffic`` in its
835        ``needs`` AND would be due at the next tick.  This recovers
836        the lazy-pull cost profile (one Prometheus query per
837        ``throughput_adjustment_interval_seconds`` in mixed mode)
838        without leaking the cadence-type concept into the
839        ScheduledTick API — plugins only see the window they
840        themselves declared via ``observation_window_seconds``.
841        """

843        # Due-check operates in the monotonic domain that
844        # ``RegisteredPlugin.last_call_at`` lives in — NOT wall-epoch.
845        # ``at_s`` (wall-epoch) is for ``ScheduledTick.at_s`` only.
846        at_monotonic = self._last_tick_monotonic + self._scale_interval

848        # no load-loop diagnostics and no FPM pull (``internal_fpm_due``

850        # throughput-only SLA planners still need the load loop for FPM.

863        )

498        try:
499            for candidate in candidates:
500                ns = candidate.replace("-", "_")
501                ns_filter = f'{prometheus_names.labels.NAMESPACE}="{ns}"'
502                query = (
503                    f"sum(increase({full_metric_name}_sum{{{ns_filter}}}[{interval}])) / "
504                    f"sum(increase({full_metric_name}_count{{{ns_filter}}}[{interval}]))"
505                )
506                result = self.prom.custom_query(query=query)
507                if not result:
508                    # No series under this namespace. Try the next candidate.
509                    continue
510                value = float(result[0]["value"][1])
511                # NaN means the series exist and the window was idle. That is an
512                # answer, so stop here: falling through would read a different
513                # router's traffic.
514                return None if math.isnan(value) else value
515            logger.info("No prometheus data for %s, returning None", full_metric_name)
516            return None
517        except (
518            PrometheusApiClientException,
519            RequestsConnectionError,
520            RequestsTimeout,
521        ) as e:
522            logger.warning("Error getting avg kv hit rate: %s", e)
523            return None
524        except Exception:
525            # A malformed response is a broken query contract, not missing data.
526            # Reporting it as absent would silently suppress the KV discount.
527            logger.exception("Unexpected error getting avg kv hit rate")
528            raise

即使 throughput_metrics_source=frontend，KV hit rate 仍读取 Router 指标。先试 Worker runtime namespace，再试 base namespace；若已有序列但窗口 NaN，则停止，不去读另一个 Router 的流量。有效 0.0 与 None 不同，缺失不覆盖 sticky 元数据。

accept length 来源与 backend 有关，随后按 speculative nextn 范围限制；冷态安全值通常是 1。它会影响 decode 每次 forward-pass 的输出折算，不等于 KV 命中率。

16 / 结论、范围与证据

Planner 将观测数据转换为控制输入：窗口流量决定需求预测，FPM 决定引擎压力与模型调优，部署状态决定哪些动作可执行。信号完整性、时间口径和 None/0 语义直接影响安全性。
