# [Feature] 模型服务智能调优与持续自我改进

## 模型服务智能调优与持续自我改进功能

### 业务目标

在实验室已有模型网关、异构算力集群、模型服务、Trace、日志指标和性能压测能力之上，建设一套**面向模型服务体验和 Coding / Agentic 任务效能的智能调优助手**：在业务 SLO 不达标、负载变化、模型或部署版本升级时，自动汇总真实服务上下文，检索历史实验与专家经验，根据瓶颈证据动态选择下一步分析和实验动作，通过 AIC 性能估算、DynoSim / SGLang Simulator 回放以及真实硬件评测，输出可追溯的优化配置与收益证据，并通过**完整过程可视化、真实业务评测与专家评价**验证效果。

在此基础上建设 **Performance Improvement Loop**：每轮实验保留成功、失败和无收益案例，使系统不仅持续优化服务配置，还能根据历史证据改进候选生成、实验选择和预算分配。以相同预算下找到更好的配置，或用更少资源达到同等目标，验证优化策略本身的进步。后续在已验证的适用范围和发布策略内，逐步引入自动灰度、效果监测与回退。

### 直接价值

- **提升用户体验和服务容量**：面向 A100 上的 021SFM-Thinking（236B）、021SFM-Instruct（236B），在模型质量及 TTFT、TPOT 达标的前提下，提高稳定请求承载能力，明确不同负载下的资源需求。021SFM-Thinking 额外区分首个生成 Token 与首个最终答案的时间。
- **提升长程任务效能**：面向 V5000 上的 DeepSeek-V4.1-Flash，结合模型调用、上下文增长、工具执行和重试分析瓶颈，提高预算内任务成功率，降低完成时间与单位成功任务的资源消耗。
- **降低调优成本**：将环境核对、数据加工、配置搜索、仿真筛选和压测对比工具化，减少人工试错与重复实验；以真实硬件结果判断收益，避免仅凭仿真分数选优。
- **沉淀可持续改进的实验知识资产**：将专家调优经验和已验证实验沉淀为具有版本、适用条件和失效边界的知识，帮助经验传承，并验证新策略能否减少后续实验成本。

### 第一阶段范围

实施分为可复现调优 L0 与策略自我改进 L1。下述第一阶段保留 Reader 实际执行、隔离实验和 Writer Dry-run；完整工程设计及后续 RL/RSI 验收见详细方案 V0.4。

- **聚焦三个重点组合**：A100＋021SFM-Thinking（236B）、A100＋021SFM-Instruct（236B）、V5000＋DeepSeek-V4.1-Flash。准确权重版本、卡型规格、推理后端、业务 SLO 和质量基线在启动阶段确认。V5000 首先完成目标模型运行资格检查，底层模型与算子适配单独评估。
- **建设调优知识库与实验记忆**：整理历史压测、现有部署配置、专家经验和失败案例，保存模型、硬件、后端、工作负载及原始证据；不将不同环境的性能数字直接作为可迁移结论。
- **Reader 实际执行**：读取真实网关请求、Token 用量、Trace、组件指标、容器日志、部署配置和 Agent 任务结果。日志及 Dynamo Request Trace 直接写 stderr，由现有容器日志系统采集，不通过 OTel Collector 采集日志；分布式 Trace 单独接入。
- **Experiment Runner 在隔离资源上实际执行**：将线上数据加工为版本化工作负载，保留到达时间、Token 长度、前缀复用和任务依赖。在预留的非生产服务资源上，按预算执行候选部署、仿真和真实压测，自动回收资源。DynoSim 与 SGLang Simulator 通过统一输入、独立执行和差异分析协作，不在首期融合两套内部时钟及状态。
- **Agent 真实评测**：固定 Agent 版本、工具链、任务集、仓库快照和执行预算，分别进行服务层 Trace 回放与真实 Coding 任务执行。回放用于筛选配置，实际测试结果用于验证任务效能，不以回放延迟代替任务成功率。
- **Writer Dry-run**：生成并行、批处理、缓存、路由、实例配比等拟议变更，输出配置差异、前置条件、影响范围、预计收益、验证证据和回退计划；首期不自动向生产下发变更。经现有发布流程由运维实施后，将真实效果与人工评价关联回实验记录。
- **完整过程可视化与复盘**：展示每一步使用的证据、瓶颈假设、选择该实验的原因、预算消耗、预测与实测差异、质量判定和失败原因。人工评价用于标注建议的可行性及解释质量，性能收益仍由可复现实测确认。
- **完成自我改进的可行性验证**：首期保存优化策略版本和完整实验记忆，建立固定策略基线；后续用保留任务上的等预算对照，验证加入记忆及更新策略是否提高搜索效率。策略生成器不能自行修改评分规则或读取保留答案。

#### 第一阶段验收

- 三个重点组合分别形成可复现基线、优化建议或无显著收益结论，附原始实验和适用范围；模型适配未通过时明确阻塞项，不计作该组合完成。
- 一条建议可追溯到业务数据、假设、候选配置、仿真、真实评测及专家反馈；失败和无收益实验同样保留。
- 请求数量、长度、时序、缓存关系和受支持的 Agent 依赖具有回放校验结果；数据缺失及不支持能力显式展示。
- A100 按延迟与质量约束下的容量验收，V5000 按真实任务成功率、时间和资源消耗验收；具体阈值在基线阶段冻结，不预先承诺统一提升比例。
- 预算、实验隔离、取消与清理有效；生产变更停留在 Dry-run 和现有人工发布流程。

#### 后续演进

执行 Loop 优化服务配置，知识 Loop 积累可迁移经验，元优化 Loop 更新调优策略。借鉴 RSI 的递归自我改进思路，第二阶段重点验证“优化器自身是否变得更高效”，再逐步扩展到 Agent 策略。模型微调、蒸馏和权重能力提升属于独立训练项目，不将推理服务加速表述为模型能力自动增强。

### 实施附件

- [详细设计与实施方案 V0.4](model-serving-autotuning-design-v0.1.md)：业务架构、部署架构、完整诊断时序、RL、Memory/数据库、Replay、工作量和阶段计划。
- 本提案将详细方案中的自动生产灰度与回退后移，首期交付发布计划及 Dry-run；发布相关工作包仍需建设配置差异、影响分析和回退产物，不因延期自动发布而直接取消预算。

### 三项关键特性

- **Data-Driven RL**：以逐请求 TTFT/TPOT 联合达标的 Goodput 为核心指标，质量、成功率和资源上限为硬约束。先用规则基线与受约束 Contextual Bandit 选择隔离实验配置，记录 Context、候选集合、动作概率和真实奖励；生产不承担探索流量。Agent 以真实任务成效为奖励，仿真分数不代替实测。
- **元优化 Loop RSI**：在 campaign 批次之间更新候选生成、记忆检索、探索和预算策略。通过固定策略、加 Memory、再加元更新三组等预算消融，验证优化方法本身是否进步。独立评价器和保留任务决定晋升，优化器不能自行改写质量门槛和评分。
- **Memory 与性能记录数据库**：原始证据、实测事实、实验经验和可执行 recipe 分层管理。每条经验带版本、适用条件、反例及失效状态；性能数据库保存环境、负载、run、指标口径、成本、决策概率和延迟反馈。建议可回溯到原始请求，不以向量相似度代替证据。

### 外部依赖与接入顺序

| 外部依赖 | 必须交付 | 验收意义 |
|---|---|---|
| 全链路 Trace | 网关到引擎与 Agent 的关联、阶段锚点、采样和查询接口 | 可构建关键路径，标出未知区间和重试，不把嵌套 Span 直接求和 |
| Dynamo 上线与 Replay | 固定版本、可运行服务、stderr 请求记录、原生 schema 和回放能力 | 真实窗口可捕获、导出、对账和回放 |
| SGLang 单实例优化 | 可运行模型、实际 KV 容量、受控参数空间和真实 Goodput 基线 | 为系统优化提供引擎基准；单实例可以使用多张卡 |

先并行完成 Trace 接入与单实例基线，再开展 Dynamo 系统回放和隔离实验，随后建立 RL 对照及元优化晋升。V5000 厂商后端单独进行资格验证，不默认继承 SGLang 的仿真或优化结论。
