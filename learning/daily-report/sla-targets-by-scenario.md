# 实验室模型服务 SLA 目标

截至 2026-11-23。本文记录日报的统计口径与每日判定，并按在线公共推理、021-SFM 重保和蚂蚁离线批推整理待确认的业务目标。日常取数与发布见[日报方案](report.md)。

## SLI、SLO 与 SLA

| 概念 | 在本方案中的含义 | 示例 |
|---|---|---|
| SLI（服务等级指标） | 衡量服务表现的可量化指标，包含统计对象与计算口径。 | 按模型计算每 5 分钟错误率，再求自然月服务可用性。 |
| SLO（服务等级目标） | 服务在约定统计周期内，对某项 SLI 要达到的目标。 | 为公共模型设定自然月可用性目标，为 021-SFM 设定重保期间的可用性目标。 |
| SLA（服务等级协议） | 向服务使用方作出的约定，通常包含适用范围、统计与验收规则，以及未达标后的处理方式。 | 重保协议可约定模型、路由、起止时间、可用性目标与未达标处理。 |

延迟 SLO 同时明确单请求阈值、达标比例和考核周期。例如当前日报的 TTFT 判定要求一个北京时间自然日内至少 95% 的有效流式请求达到单请求 5 秒阈值。

## SLI 统计（@陈昕）

### 当前日报判定

日报从 Higress Loki 取数，覆盖科研看板的六个模型及 021SFM-32B-Thinking。匹配七个生产模型路由和推理接口的 zero2x 请求计入。每天按模型统计前一北京时间自然日。主表按匹配网关日志条目数降序排列。[取数和判定脚本](run_report.py) · [11 月 22 日正式日报](https://zjic.zhejianglab.com/control/reportSquare/read?report=rsb-1320818356024680448&date=2026-11-22)

| 日报指标 | 统计口径 | 每日目标 |
|---|---|---:|
| 请求可用率 | `1 − 全天 5xx 条目数 ÷ 全天有效请求条目数`。有效请求取 HTTP 2xx、3xx、5xx，4xx 和状态码 0 等未归类记录排除。 | **≥ 99.5%** |
| 流式请求 TTFT 达成率 | 有有效首段计时的网关流式请求按外部请求 ID 去重。单请求以网关首次流式响应体回调耗时 **≤ 5 秒**为达标。 | **≥ 95%** |
| 流式请求 TPOT 达成率 | 对 HTTP 2xx、无网关异常标记、计时完整且至少输出两个 Token 的流式请求，按外部请求 ID 去重，再计算 `(流关闭耗时 − 首段耗时) ÷ (输出 Token 数 − 1)`。单请求阈值为 **≤ 50 ms/token**，Kimi-K3 为 **≤ 200 ms/token**。 | **≥ 95%** |
| 429 比率 | `429 条目数 ÷ 同模型全部匹配网关日志条目数`。独立明细表仅展示出现 429 的模型，按 429 条目数降序排列。 | 诊断项 |

综合 SLA 按请求可用率、TTFT 和 TPOT 三项判定，使用未舍入的比例。任一可判定项低于目标，综合判为未达标。三项均达标时综合达标。其余情况显示暂无法判定。缺少相应有效计时或 Token 字段的请求从延迟分子和分母同时排除。无有效样本时，该项暂无法判定。

日报的请求可用率对全天有效请求按请求量直接汇总。下文业务 SLO 的服务可用性按 5 分钟窗口等权汇总，并考虑需额外证据确认的入口故障。两种指标的统计周期和权重不同。[独立可用性观测报告](availability/2026-11-19.html)

预发和正式使用同一份 HTML。每天北京时间 08:00 生成并发布预发，09:30 校验预发摘要后发布正式。数据洞察放在主表之前，提到当日 SLA 未达标的模型时标红名称。洞察展示 5xx 影响、延迟超阈值贡献和较前一日的最大变化。

### 月度与重保可用性统计

- 独立可用性口径按外部请求 ID 去重，排除 HTTP 4xx。429 单列供归因。平台侧限流是否计入重保失败，由重保要求确认。
- 每 5 分钟计算 `服务侧有效失败请求数 ÷ 有效请求数`。HTTP 5xx 计入失败。确认由平台故障导致未到达网关的真实请求，同时计入失败数和有效请求数。状态码为 0 或归因不明的记录单列。服务可用性为 `1 − 纳入考核的 5 分钟窗口错误率的算术平均值`。参考百炼，采集已核实完整且有效请求少于 5 个的窗口按 0% 错误率计。
- 重保开始前登记模型和路由白名单、起止时间和适用流量。重保结论按同一窗口方法单独统计。有效请求数、5xx 数、低流量窗口数与缺测窗口数用于对账。当前定时日报尚未按重保时段或自然月生成单独结论。
- Higress Loki 提供到达网关的请求记录。网关外探针用于确认入口可达性，结合客户端记录核实未到达的真实请求。无法核实的入口故障窗口标记缺测，受影响周期的正式可用性暂无法判定。

## 业务 SLO（@潘淑）

目标栏可留空，确认后填写。请求级延迟目标需同时填写单请求阈值和达标比例。

| 业务场景 | 指标（SLI） | 业务目标（SLO） | 考核范围 |
|---|---|---|---|
| 在线 · 实验室公共模型 | 模型推理服务可用性 | | 建议按模型、北京时间自然月考核。 |
| 在线 · 021-SFM 重保 | 模型推理服务可用性 | | 指定模型、路由、流量和重保时段。 |
| 在线 · 流式推理 | 请求级 TTFT 达成率 | | 确认业务承诺周期、适用模型、输入长度和流量条件。 |
| 在线 · 流式推理 | 请求级 TPOT 达成率 | | 确认业务承诺周期、适用模型、输入长度和流量条件。 |
| 离线 · 蚂蚁批推 | 批推服务可用性 | | 按双方确认的验收口径、适用业务和考核周期执行。 |

原稿评审参考值为公共模型月度可用性 ≥ 99.0%，021-SFM 重保可用性 ≥ 99.9%。沿用 5 分钟窗口等权口径时，重保 99.9% 对应平均窗口错误率 ≤ 0.1%。重保验收时需确认是否另对整段重保期的 `5xx 总数 ÷ 有效请求总数` 设限。

### 离线场景：蚂蚁批推

服务可用性以蚂蚁提供并经双方确认的要求为准。待补充原始协议或验收材料，优先确认以下口径：

| 待确认项 | 需要明确的内容 |
|---|---|
| 可用性目标及统计周期 | 承诺百分比、考核时区、适用业务及计量单位。 |
| 成功标准 | 蚂蚁要求考核的是提交接口可用、任务执行成功，还是截止时间前按约交付完整且可用的结果。 |
| 分子与分母 | 如何界定有效任务、平台拒绝或未受理的有效提交，以及重试、部分成功、主动取消和客户输入错误的归属。 |
| 对账依据 | 项目和任务 ID、业务日期、提交及结束时间、终态、失败归因和结果交付记录。 |

若蚂蚁以按时交付为验收点，可采用 `在约定时限内交付合格结果的有效任务数 ÷ 应交付的有效任务数`。任务时限和合格标准以客户验收要求落地。
