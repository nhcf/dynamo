33//!
34//! Two independent limits govern entry to the engine, and a request enters only
35//! when both have room:
36//!
37//! - The **engine request limit** bounds admitted requests that have not
38//!   finished. A request holds request capacity from admission until its
39//!   response stream ends or is dropped, however long it then runs.
40//! - The **engine request waiting limit** bounds admitted requests still
41//!   waiting for their engine's output. A request holds waiting capacity from
42//!   admission until the gate observes its first generated token or its
43//!   completion, whichever comes first, on every worker role (see
44//!   [`ResponseOutput::ends_wait`]). Interim responses — metadata or control
45//!   only, such as a disaggregation bootstrap announcement or a cache report —
46//!   leave it waiting. The backend classifies its own responses through
47//!   [`AdmissionResponse`]; the gate never parses a payload. Obtaining the
48//!   stream is not a response.
