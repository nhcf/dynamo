02 / 三条控制闭环与一条请求路径

部署闭环用户 → Admission → Kubernetes API → DGD controller → 选定 provider program → DCD / provider workload → Pod / Service → status / watch → 再调谐
容量闭环Frontend / Worker → Prometheus、FPM、部署状态 → Planner → DGDSA scale 或 DGD patch → Operator → Pod 可用 → 反馈
成员闭环Worker 注册 → DynamoWorkerMetadata；EndpointSlice / Pod readiness → Runtime join/cache → DiscoveryQuery → Frontend / Router 的成员集合
推理路径Client → Frontend / KV Router → Prefill / Decode / Engine；不要求每次请求都经过 Operator 或 kube-apiserver

架构图 Mermaid 源文件 · 调谐时序图 Mermaid 源文件。上方架构以离线 HTML 展示，不依赖在线 Mermaid 渲染服务。

运行中的请求可能继续执行，但控制面故障会影响新实例注册、成员更新、扩缩容、部署和恢复。影响依赖缓存、watch 和 provider 状态，不能简单断言控制面故障一定让所有请求立即失败，或完全没有影响。
