01 / 结论：请求主链可串，跨数据面全覆盖需补齐

当前 Dynamo 有 PD 请求主链的分布式上下文传播与部分因果关联能力，但不能把“Request Plane + KV 存储 + Events + NIXL 底层传输”整体视为已经开箱即用的一棵完整 OTel trace 树。

本章固定代码 2f296b592，分析日期 2026-10-29。源码能力不同于线上已验证能力；未运行 PD 请求、抓取线上 Trace 或修改部署。外部引擎及 NIXL 版本可能独立变化。

范围支持程度判断依据
HTTP Frontend → Runtime 请求传输 → Worker已有传播契约提取 W3C Context、注入请求 Header、接收侧 set_parent
Prefill → Decode handoff支持特定路径的 OTel LinkCompleted handoff 携带 worker_trace_link；Bootstrap 路径单独处理
Engine generate 与引擎内部框架与参数接口已有；内部覆盖依 backendengine.generate、Context.trace_headers、各引擎调用参数
KV 存储/缓存操作部分本地 instrumentation / ID / 计时；未形成所审路径的统一跨异步 trace 契约调度请求有 request_id/uuid；后台批处理和 TimingTrace 不能自动形成因果树
KV / FPM / 路由状态 Event Plane通用传输没有自动 W3C 传播EventEnvelope 无 Context；NATS publish 无 headers；ZMQ frames 无额外 trace metadata
NIXL 传输遥测与局部诊断可用；不是通用请求级 trace 保证KV transfer executor 负责 create/post/异步完成；需要明确绑定发起请求与完成回调
判断“全链路”要同时满足：上下文传播、操作 span、正确开始/完成边界、异步关联与导出。能搜到同一个 request_id，或者能画出传输耗时直方图，都不足以证明这些条件。

02 / 把请求控制流与 KV 数据流分开

Request Plane客户端 W3C Context → Frontend HTTP span → Router / Dispatch → Prefill Worker → Decode Worker → SSE 返回
Engine KV 数据面Prefill KV cache ↔ Engine connector / NIXL ↔ Decode KV cache；具体引擎可能使用 pull、push 或异步 bootstrap
KV 分层存储GPU ↔ CPU ↔ SSD / 远端，由所用 KVBM、引擎 connector 或其他缓存系统负责
EventsWorker / Router / FPM publisher → NATS 或 ZMQ → 索引/订阅消费者；不是请求 RPC

PD 分离不要求所有 KV 都经过 Dynamo KVBM。vLLM/SGLang/TRT-LLM 的 connector、Dynamo KVBM、LMCache 等是不同实现边界；不能用一个 executor 的行为代替所有引擎数据面。

Span Link 表示因果关系，不会把两个已有 Trace ID 强行合并。共享缓存、批量搬运和广播事件通常是多对多关系，不适合全部硬挂成单个请求的子 span。

11 / 如何验收“串起来了”

测试场景必须核对的证据
PD cache miss同一个请求的 Frontend、Prefill、Decode Context；parent/links 与 worker identity
已完成 Prefill handoff前驱 worker link 出现在 Decode engine span 的 links；不要只看同名属性
Bootstrap/并行 handoff分别验证其上下文路径，不能借用 Completed 分支的结论
跨端 KV transfer发起、远端接收/处理、完成/超时 span 与 transfer_id 的实际关联
CPU/SSD/远端 cache miss命中/未命中、load起止、等待时间和数据位置，是否有真实 span
KV stored/remove 事件生产与消费 Context/Link，事件去重/重放/批量后的因果关系
共享 prefix、多并发、批量迁移没有串错请求；能表达一个动作影响多个请求
失败/取消/重试span 完成状态正确，不出现永不结束或仅凭请求 ID 拼起来的链

先用低并发受控请求与测试父 Context，分别触发 miss、hit、offload、传输失败；检查原始 OTLP 数据中的 trace_id、span_id、parent_span_id 和 links。Collector 收到数据只证明导出链路，不能证明应用的因果关系。
