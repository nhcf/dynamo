ACK Request Plane Trace：主链路 Span 设计

对象：nhss-job / dynamo-qwen38-27b-mixed-demo，Frontend、prefill、decode、aggregated 各一副本，Worker TP=4，Request Plane=tcp。本文只回答一个问题：一次请求在哪些位置产生 span、这些 span 之间靠什么关联、哪些是线上 1.4.1 可以指望的、哪些只是 1.7.0 的设计目标。落地步骤与验收标准在 工作清单，读图与查询方式在 链路走查。

因此下文每个 span 都标注保证程度，共三级：

  • 稳定：由 OTel 语义约定或长期存在的实现保证，1.4.1 上大概率可直接看到，仍以现场核对为准。
  • 需核实：代码中存在，但受日志级别、采样或环境变量控制，默认配置下可能看不到。
  • 仅 1.7.0：本仓库设计目标。私有镜像若不包含对应提交，则不产生这些 span，验收不得以“应该有”为前提。

本文不做“1.4.1 与 1.7.0 完全相同”的推断。核对方法是工作清单 T01 的包版本与 --help 取证，而不是比对文档。

2. 请求主链路逐跳清单

主链路定义为：外部客户端 →（可选上游网关）→ Frontend HTTP 处理 → 路由/派发 → 传输层（tcp）→ Worker 处理 → SGLang 引擎 → 响应流式回传 → 客户端。下表按时间顺序排列，不含旁路（metrics、KV events、NIXL 传输）。

3. Dynamo lifecycle schema：根与 13 个阶段

lifecycle 用固定 target dynamo.request_lifecycle 记录一次请求在各阶段的归属。契约：schema v1、profile generic.v1、mode core。

根 span 在 lib/runtime/src/telemetry.rs 185–187 创建，名称 request.lifecycle，强制带 dynamo.request.id。生产侧在 openai.rs 2620 以 .instrument(request_lifecycle.or_current()) 挂到请求 future 上；没有 lifecycle 上下文时退回当前 span，不额外造树。

4. 引擎侧 span 与 P/D Link

engine.generate（adapter.rs 244–261）是 Dynamo 看到的引擎调用边界。它除了常规属性，还在 270–285 建立一个 OTel Link，指向前驱阶段：

SpanContext::new(trace_id, span_id, TraceFlags::SAMPLED, true /* is_remote */, TraceState::default())

Link 而非 parent 的原因：disaggregated 场景下 prefill 与 decode 是两个独立执行体，谁也不是谁的时间父节点。验收时不能只按父子关系判断，要同时看 Link。前驱上下文缺失时，worker_trace_link 会以 trace 级别告警，因此“看不到 Link”可能是级别问题而非实现缺失。

源码原文：WorkerOperationPrefill and WorkerOperationDecode are coarse Dynamo runtime boundaries around the worker operation; they are not direct engine execution measurements.即 worker.operation.prefill/.decode 的耗时是 runtime 边界，不等于引擎内部的 prefill/decode 执行时间。要引擎级数字，必须靠 §2 #9 的引擎 span。

项目为什么不算主链路
Worker :9090/metrics、Frontend :8000/metrics、PodMonitor指标抓取，与 trace 采集是两条独立管道。指标正常不证明 trace 已开启。
nixl:19090、bootstrap 12345KV 传输与握手端口，不是 OTLP 目标，也不应作为 trace endpoint 填写。
ZMQ KV events（tcp://*:5557）Event Plane，供路由决策使用，不承载 span。

6. 关联键、采样与缺口判定

  • 主关联键是 Trace ID，由入站 traceparent 固定；x-request-id 只用于辅助检索日志，不能替代 Trace ID 判定链路完整性。
  • 第二关联键是 dynamo.request.id。引擎 span 可能不含该属性，此时用 Trace ID + Link 关联。
  • 采样要在三处对齐：上游是否透传 sampled=01、Dynamo 侧 OTEL_TRACES_SAMPLE_RATIO、引擎与 Collector 的采样。任一处丢弃都会造成“看起来断链”的假象。联调期统一设为 1.0。
  • 判缺口顺序：① 该 span 版本是否存在（对照 §2 保证程度）→ ② 日志级别是否放行（handler span 常见）→ ③ 采样是否丢弃 → ④ 传播是否断开（tokio::spawn 未用 in_current_span() 会丢当前 span）→ ⑤ Collector 是否拒收。
  • 开销：引擎 span 粒度由 SGLANG_TRACE_LEVEL 控制，本仓库对 1.4.1 建议先用 1 或 2，不默认开高详细级别。
