追加到 prefill、decode、aggregated 的现有完整命令

--enable-trace \
--otlp-traces-endpoint <真实Collector-FQDN>:4317

引擎使用裸 host:port；runtime endpoint 使用 http:// URL。先核对 command 是 shell 字符串还是 Python argv，追加到正确位置；不要用只有这两个参数的 args 数组覆盖完整启动配置。--enable-otel 是示例 launch 脚本开关，不直接添加到 python -m dynamo.sglang。

可选在 Worker 设置 SGLANG_TRACE_LEVEL=1 或 2，先确认镜像支持，不默认启用高详细级别。这些 SGLang 开关依据 Dynamo 1.4.1 官方说明；私有镜像仍需现场验证。

本仓库源码为 1.7.0。DYN_LIFECYCLE_TRACE_ENABLED、当前新增 span 名称及 P/D Link 实现不作为线上 1.4.1 的既定能力或必配项；验收按实际镜像契约确认。

5. 验收入口、请求和通过标准

使用有 Endpoints 的 Frontend Service。旧 dynamo-qwen38-27b-prod-nodeport:32081 的 Endpoints 为空，不用它验收，也不把修复旧 NodePort 作为 trace 前置条件。

# 终端 A：本机端口转发；结束后 Ctrl-C
kubectl --kubeconfig "$DYNAMO_TRACE_KUBECONFIG" --context "$DYNAMO_TRACE_CONTEXT" \
  -n nhss-job port-forward svc/dynamo-qwen38-27b-mixed-demo-frontend 18000:8000

# 终端 B：每次测试新建 W3C ID
DYNAMO_TEST_TRACE_ID=$(python3 -c 'import secrets; print(secrets.token_hex(16))')
DYNAMO_TEST_PARENT_ID=$(python3 -c 'import secrets; print(secrets.token_hex(8))')
printf 'Trace ID: %s\n' "$DYNAMO_TEST_TRACE_ID"

curl -N --max-time 120 http://127.0.0.1:18000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -H "traceparent: 00-$DYNAMO_TEST_TRACE_ID-$DYNAMO_TEST_PARENT_ID-01" \
  -H "x-request-id: trace-check-$DYNAMO_TEST_TRACE_ID" \
  -d '{"model":"Qwen3.8-27B","messages":[{"role":"user","content":"请用一句话介绍分布式推理。"}],"max_tokens":32,"stream":true}'

此请求只检查入口/传播，不会强制 PD。先按 T02 确认该版本路由选择/过滤方式；无法可靠选择时，在独立验收入口或隔离测试 DGD 验证，不能直接停用现有 aggregated/igd Worker。curl 提供外部 parent ID，但不导出客户端 span，界面不展示外部父节点不等于断链。

用例通过条件
A：PD 正常 SSE本 DGD 的 P/D Pod 确实参与；Frontend、请求传输/处理和 SGLang 引擎 context 关联正确；检查 Trace ID、父子关系及该版本支持的 handoff Link。不能只凭 request_id 判定。
B：aggregated 正常 SSE独立得到 Frontend→aggregated→SGLang 关联，不替代用例 A。
C：取消/错误记录时间、span 结束和取消/错误状态，排除长期悬空；实际启用重试时增加重试用例。
D：真实上游网关（若有）真实入口 context 正确传递，网关自身 span 已导出；否则仅声明从 Frontend 起的覆盖范围。

同目录 evidence/ 建议保存：配置快照、imageID/包版本、请求 ID/Trace ID、实际参与 Pod、trace 导出/截图、Collector 接收/丢弃统计及验收时间。TP=4 的 rank span 覆盖以实际引擎支持为准，不机械要求四份相同跨度。

6. 旁项与覆盖边界

  • PodMonitor system-0/system-1：属于指标配置，另行核查；不能直接推断“每张 GPU 缺少抓取”，TP=4 不要求四个 Pod metrics 端口。
  • Planner/Router PodMonitor：监控对象存在不证明本 DGD 有对应独立组件。
  • 旧 NodePort、CRD storage 迁移、CPU limit、Operator 租约历史：另排维护，不作为基础 trace 硬前置。
  • Frontend 无探针：本次纳入发布恢复检查，补探针可单独实施。
  • NIXL :19090、ZMQ KV events、KV 存储：不作为 trace 开关；本清单不承诺底层传输、事件与存储操作已请求级全覆盖。
